# ATHAR | أثر — Operational QA Checklist

Operational QA checks the **pilot process**, not only the website.

- [ ] A facilitator can find the correct document in under two minutes using the index/file map.
- [ ] Participant code can be recorded without name/contact data.
- [ ] A defect can be logged and assigned severity/owner.
- [ ] An S3 fictional drill causes a pause and correct escalation route.
- [ ] Daily huddle produces an explicit decision and owners.
- [ ] Shared-device state reset can be completed and verified.
- [ ] Arabic facilitator can use Arabic briefing/session script without relying on English operational labels.
- [ ] Observer can distinguish product defect from learning observation.
- [ ] Baseline change can be recorded without silently pooling results.
- [ ] Closeout/Go-No-Go route is understood before data collection starts.

Failures become readiness issues; resolve them before the planned cohort.
