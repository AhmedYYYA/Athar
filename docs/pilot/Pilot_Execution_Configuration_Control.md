# ATHAR | أثر — Pilot Configuration Control

## Controlled items
- immutable website baseline SHA;
- Stage 7 execution-package SHA/milestone;
- curriculum/evidence rules inherited from locked milestones;
- approved operating documents used by facilitators;
- tracker schema/version.

## During shakedown/pilot
A proposed change must be classified:
- **Documentation clarification:** no change to participant experience or evidence interpretation.
- **UI/technical fix:** participant experience changes but curriculum/evidence logic does not.
- **Material learning/safety/evidence change:** curriculum, safety guidance, evidence meaning or session interpretation changes.

UI/technical fixes require relevant regression/browser QA before the affected flow resumes. Material learning/safety/evidence changes require explicit Pilot Lead plus relevant safeguarding/education review and create a new comparison boundary.

## Record
For every baseline change record: previous SHA, new SHA, reason, issue ID, authorization, verification, effective session/date, and whether earlier/later observations may be pooled.

Never silently edit a live pilot and treat all observations as if they came from one product version.
