# ATHAR | أثر — Critical Pilot Execution Rules

1. No real child session without approved participation conditions and child assent.
2. No real participant data in the public GitHub repository.
3. No open S3 issue at cohort launch.
4. No silent product baseline change.
5. No answer-giving disguised as facilitation.
6. No interpretation of supported evidence as failure.
7. No unnecessary private/sensitive data capture.
8. No probing safeguarding disclosures through ATHAR.
9. No claim that a bounded pilot proves production readiness.
10. A child may stop at any time.
